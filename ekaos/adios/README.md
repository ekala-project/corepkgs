# ekaos on lladaios (adios)

The `lladaios` flake input (`github:llakala/lladios`, a fork of
adisbladis/adios) provides the module system for ekaos configuration,
replacing `lib.evalModules` + `mkOption`.

Status: FULL PORT. Every module under `ekaos/modules/` (199 files) is
mirrored under `ekaos/adios/modules/` in adios syntax:
`{ options, inputs, modules, impl, mutations, assertions }` with korora
types (`adios.types`). The two exceptions are `module-list.nix` (replaced by
the generated `modules-tree.nix`) and `services.nix` (ported as
`services-iface.nix` to avoid clashing with the `services/` tree node).

The legacy NixOS-style tree under `ekaos/modules/` is still present and
still authoritative for system builds. Cutover (deleting it and switching
`ekaos/eval-config.nix`) is blocked on the gaps listed below.

## Layout

- `default.nix` — entry point: `(adios { modules = import ./modules-tree.nix ...; }) { }`.
  `pkgs` is threaded to every module (`{ types, lib, pkgs, ... }:` where
  `lib` is adios.lib with the merge helpers).
- `modules/` — ported modules, same relative paths as `ekaos/modules/`.
  Non-module files are copied verbatim (`security/wrappers/wrapper.nix`,
  `wrapper.c`).
- `modules-tree.nix` — GENERATED by `gen-tree.py`, do not edit. Builds the
  nested adios tree (`modules/boot/kernel.nix` →
  `modules.boot.modules.kernel`). Re-run the generator after
  adding/removing modules.
- `CONVERSION.md` — the NixOS→adios translation spec used for the port.

## Evaluating

```nix
let
  tree = import ./ekaos/adios { inherit adios pkgs; };
in
{
  kernel = tree.modules.boot.modules.kernel { kernelParams = [ "quiet" ]; };
  getty = tree.modules.services.modules.getty { ttyCount = 4; };
}
```

## Validation

Whole-tree validation (2026-09-26): every impl-bearing module called with
`{ }` against corepkgs pkgs — **197/197 pass, 0 failures**
(23 pure namespace nodes). Method notes:

- `inputs.*.from` paths are statically audited (scope rule: siblings via
  `{ parent }: parent.<leaf>`, cross-tree via `{ root }: root.<path>`).
- Nix lists are space-separated: a ported `},` comma bug and a
  `!a or b` precedence bug (parses as `(!(a or b))`) were found and fixed.
- korora `types.path` rejects strings (legacy accepts them): all
  option-position uses are `types.pathLike`.
- adios evaluates all option defaults eagerly (NixOS is lazy), so
  `pkgs.<missing> or (throw ...)` package defaults became
  `nullOr derivation` + `or null` with an enable-gated assertion
  (plymouth, zfs, iio, earlyoom, fprintd, thermald, prometheus,
  queued-build-hook, fwupd, docker, terminal-exec).
- Legacy `lib.mkIf cfg.enable` assertion gating is preserved as
  `(!options.enable) || ...` (nvidia, acme).
- Two latent legacy bugs fixed in the port: texlive defaulted to a package
  *set* (now `combined.scheme-basic`); facter cpu detection threw on an
  empty report (now defaults false).

## Remaining cutover gaps (all marked `TODO(adios-cutover)` in-tree)

1. **Impl-output addressability**: adios inputs only see sibling *options*,
   never impl results. Consumers of legacy internal options
   (`system.build.toplevel`, `initialRamdisk`, whole-subtree `services.*`
   reads in systemd/runit/port-contracts/package-manifest, prometheus
   auto-discovery) use `or`-fallbacks or stubs. A merge-back/aggregation
   layer is needed before these modules behave identically.
2. **extendModules**: `system.build.{systemd,runit,launchd,rcd}` variants
   are valueless stubs; adios has no re-fixpoint equivalent.
3. **Helper rewrites**: `ekaos/lib` builders (`make-initrd.nix`,
   `make-iso9660-image.nix`, `make-disk-image.nix`, timer/tmpfiles helpers)
   still require nixpkgs lib; adios-aware rewrites pending.
4. **Priority loss**: `mkDefault`/`mkForce`/`mkBefore`/`mkAfter`/`mkOrder`
   became plain values; conflict/override semantics differ at the margins.
5. **Submodule validation loss**: dynamic `attrsOf (submodule ...)` became
   `attrsOf attrs` with `or`-fallback defaults in impl.
6. **Consumers still on legacy**: `ekaos/eval-config.nix`, `ekaos/lib/testing`,
   `dev-shell/`, `services/` tests/examples all use `lib.evalModules`.
